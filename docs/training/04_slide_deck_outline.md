# B2B Customer Development SOP v3.1 · Companion slide-deck outline

> 24 slides for the 45–60 minute full version; the 20-minute condensed version uses the 12 slides marked ★.
> Each slide gives: title / on-screen points (no more than 5 lines) / visual suggestion / speaker note (which part of the training script it maps to).
> The flowchart v3.1 PNG can fill one slide whole; afterwards each block uses a cropped, enlarged section.

## Slide 3 ★ Overall structure: a loop
- Top: Install Gate + Data Access Layer
- Middle: Step 0 + seven steps
- Left: self-replenishing engine (four-axis rotation)
- Bottom: Step 8 review → writes back into the files at the top
- Visual: full flowchart with an arrow marking the bottom → top return path
- Note: stress "not a line, a loop"

## Slide 4 ★ The three gate checks
- Check 1 Company profile: industry, offer type, product facts, differentiators ≥2, buyer titles ≥1
- Check 2 Soul Seven Kit: content health check, not just flipping a true
- Check 3 User attestation: content fingerprint recorded
- Fail any check → every search / send script refuses to run
- Visual: gate band of the flowchart, enlarged
- Note: explain why the fingerprint matters

## Slide 5 Content fingerprint
- At attestation the content fingerprint of profile + kit is recorded
- Any later edit → scripts stop → read-back and re-confirmation required
- Prevents: profile written three months ago, product changed, AI still using old wording
- Visual: two-column before / after
- Note: skip in the condensed version

## Slide 6 ★ Data Access Layer: five boxes
- External exports (SaaS / customs / CRM) → inbox folder → import reminder
- Own customer DB import (required at install): existing / do-not-contact / peers never enter the cold pool
- Sending channel: mailbox key · hosted multi-mailbox warm-up · MCP drafts
- CRM sync: export to any CRM; push is a dry run by default
- Data Triggers: daily scan, only reminds and stops, never sends
- Visual: data-access band of the flowchart, enlarged
- Note: stress "the tool ships no customer database"

## Slide 7 Sending channel, one of three
- Single mailbox: business mailbox client key, environment variables only
- Hosted multi-mailbox: ramps up by warm-up tier (tiers are adjustable defaults), auto-pause when bounce rate is exceeded
- MCP connector: drafts only, every e-mail approved by a person
- Every e-mail carries an unsubscribe header and an opt-out line
- Visual: three-column comparison table
- Note: state that the warm-up numbers are defaults, not an industry standard

## Slide 8 Data Triggers: ten situations
- Pool low / new import file / follow-up due / new reply / bounce anomaly
- WhatsApp lead / warm-up tier up / mailbox paused / CRM pending sync / weekly review due
- The only automatic action: bounce anomaly → pause that mailbox
- Everything else goes into the to-do queue for a human decision
- Visual: ten icons in two rows, the automatic action in a different colour
- Note: ask "if the system sent automatically, what is the worst case?"

## Slide 9 ★ Self-replenishing engine: four-axis rotation
- Depth, fastest: companies → decision makers → deep-dive the stock
- Reach: regions from near to far
- Height: customer tiers from high to low
- Breadth, slowest: core terms → broad terms
- Red line: sendable <100 or reserve <30 days → replenish
- Visual: four gears, size showing rotation speed
- Note: ask "why is Depth fastest and Breadth slowest" before giving the answer

## Slide 10 Step 0: Omni-channel Review
- Look at last round's conclusions before each round
- Win patterns + WhatsApp review + last week's write-back
- "This week's conclusions" = start of this round
- Visual: one sentence in large type
- Note: merge into slide 9 in the condensed version

## Slide 11 ★ Step 1: Search Candidates
- Public search only: 15 discovery channels, 10 social platforms, 30 procurement-chain titles
- Any action that needs a login is marked "manual"
- Visual: wall of channel icons
- Note: explain "the scripts only generate queries, they never log in for you"

## Slide 12 ★ Three Iron Rules of Search
- Check the DB first: not truly new → does not come in
- Funnel diagnosis: duplicates >40% or named rate <20% → change direction
- Pending into the pool: wide entry, strict sending
- Visual: three banners
- Note: ask "why wide entry and strict sending"

## Slide 13 ★ Step 2: Background Research and evidence tiers
- The brand name does not decide the need; research does
- S1 company's own statements / S2 credible third party / S3 guess
- ≥1 S1 or 2 independent S2 before tagging; S3 only → human decides
- E-mails quote S1 and S2 only
- Visual: three-tier pyramid
- Note: give the "Organic" counter-example

## Slide 14 Step 3: Need Positioning, dual tags
- Need tag → which product line
- Solution tag → which hook
- Rule conflict → no send, to a human
- Visual: two tag cards
- Note: merge into slide 13 in the condensed version

## Slide 15 ★ Step 4: Write Content
- Recipient's native language · ≤120 words · plain text
- S1 / S2 facts only
- Follow-ups must change angle and bring news
- Three pre-send checks: named mailbox / de-duplicated / notes complete
- Visual: structure frame of a sample e-mail
- Note: ask how long before they close a cold e-mail

## Slide 16 ★ Step 5: Send
- Dry run first, read every e-mail, confirm, then send
- Named decision makers only
- Recipient's local weekday window; outside the window = deferred, not dropped
- ≤200 / day · 30 s interval
- Hosted mailboxes rotate by warm-up cap, auto-pause when bounces exceed the threshold
- Visual: pre-send checklist style
- Note: stress "the only truly outbound action"

## Slide 17 ★ Step 6: Follow-up Management
- 24–48 h bounce / reply scan, mailbox opened read-only
- E-mail cooldown 3 / 3 / 10 days, 4 e-mails at most; social 1 / 3 / 7 / 21 days
- One customer, one channel per day
- Four exits: bounce → blacklist · reply → human · 4th e-mail → stop generic mailboxes, switch channel · order → review
- Visual: four-branch flow
- Note: ask "why stop at the 4th e-mail"

## Slide 18 Step 7: WhatsApp Trigger
- Triggered, not first choice: 3 e-mails no reply / high value / customer gave number
- Validate the list first: format, duplicates, empty messages, placeholders
- Send to your own test number first
- One by one · 8–15 s interval · hard stop at 200 · screenshot audit
- Visual: WhatsApp band of the flowchart, enlarged
- Note: the cost of a ban is the whole number

## Slide 19 WhatsApp dedicated review
- Funnel / by region / by need / by hook
- Write back the won channel
- Visual: four small chart placeholders
- Note: skip in the condensed version

## Slide 20 ★ Step 8: Win Review and write-back
- Wins go into the case library; pain points must be human-confirmed
- Omni-channel review: region × tag × hook × channel
- Win attribution: e-mail vs WhatsApp, which region to weight
- Kit write-back: where it went wrong → that file, change the rule
- Re-check → next round
- Visual: review band of the flowchart, enlarged, with the upward arrow highlighted
- Note: callback to the first opening question

## Slide 21 Data layer and the three iron rules
- Customer DB · send history · blacklist · WA contacts · success cases · pipeline · mailbox usage · CRM log
- Scripts read customer data and never edit it on their own
- Pain points, tags, sending, CRM pushes, quotes: human decisions
- Keys via environment variables only
- Visual: bottom data band, enlarged
- Note: merge into the closing in the condensed version

## Slide 22 ★ Six brakes
- Gate · fingerprint · dry run · window · cap · human sign-off
- Visual: six brake-pad icons in a row
- Note: callback to the third opening question

## Slide 23 ★ Back to the three questions
- Traceable: one e-mail = one customer + one tag + one piece of evidence + one send record
- Transferable: the gate tells the new hire what to fill in, the flowchart tells them what to run
- Brakes: six

## Production notes

- Use the same flowchart as the visual spine throughout: the full chart on slide 3, then a cropped section for each block, so the audience always knows "where on the chart we are".
- All numbers (120 words, 200 e-mails, 30 seconds, 3/3/10 days, 1/3/7/21 days, 40%, 20%, 100 leads, 30 days, 8–15 seconds) come from the rules inside the skill; do not change them on screen. If the warm-up tiers are shown, they must be labelled "adjustable default".
- Never put a real company name, mailbox or phone number on a slide; examples use example domains only.
