# Industry adaptation guide (any industry in 10 minutes)

> The process of this skill (search → research → tag → write → send → follow up → WhatsApp → review) is the same for every B2B business.
> Only three things differ between industries: **who to find**, **where to find them**, and **how to let them start with low risk**.
> They live in the profile's `targeting`, `search` and `offer` sections; no other script or rule changes.

---

## 1. Three-step adoption

```
1. Pick an industry pack (method-level suggestions, optional)
   python3 scripts/onboarding.py packs                # list the 13 built-in packs
   python3 scripts/onboarding.py pack saas_software   # all suggestions of one pack
   python3 scripts/onboarding.py init                 # create a blank profile
   python3 scripts/onboarding.py apply-pack saas_software
      → writes suggestions only into method-level fields that are still empty: customer tiers, decision roles, channel terms, intent terms, recommended channels, exclude terms
      → never writes company facts (brand, contacts, product terms, selling points, offer.*)
      → user_confirmed is reset to false automatically

2. Fill in company facts (interactive ask, or the AI asks item by item per onboarding_questions.md)
   business.industry / business.offer_type / company.* / product.* / offer.* / contact.*

3. Read back → the user rewrites each item in their own words → explicit confirmation → attest activates
```

What the pack writes is only a "starting draft". For example the `L1_oem` tier written by `industrial_b2b` should become your real customer types ("injection-moulding machine makers", "pump and valve OEMs") so the queries become precise.

## 4. Two tags: industry-independent research conclusions

| Tag | Question answered | Values | Defined by |
|---|---|---|---|
| `need_tag` | **which** of your product / service lines does the customer need? | your own: `positioning.need_tags` (e.g. `line_a`/`line_b`) + reserved `multi`/`unknown`/`review` | you |
| `solution_tag` | **what matters most** in the customer's decision? | 11 generic decision drivers: `compliance` `sustainability` `quality_upgrade` `cost` `speed` `low_commitment` `innovation` `exclusive_custom` `one_stop` `dedicated_service` `strategic_scale` (+ `open`/`unknown`) | fixed, cross-industry |

- E-mail hooks are picked by `solution_tag` (`industry_playbooks.md` §7); the scripts fall back to `hook_type` / `need_tag`.
- For industry rules such as "line X and customer type Y cannot coexist", write them in `positioning.tag_rules`; `conflict-check` enforces them automatically:

```json
"positioning": {
  "need_tags": ["line_a", "line_b"],
  "conflict_groups": {"need_tag": [["line_a"], ["line_b"]]},
  "tag_rules": [
    {"if_field": "variant_tag", "equals": "on_premise", "forbid_field": "solution_tag",
     "values": ["low_commitment"], "reason": "On-premise deployment has no low-commitment trial"}
  ],
  "hooks": {"cost": "Teams switching to us usually cut {lead}. {second}."}
}
```

## 6. Self-check after adoption

```bash
python3 scripts/onboarding.py start                 # what to fill in right after installing (three-check status)
python3 scripts/onboarding.py kit-check             # Soul Seven Kit content health check, must be 7/7
python3 scripts/onboarding.py check                 # required fields (incl. business.industry / offer_type) + confirmation status
python3 scripts/search_customers.py social --regions <one target country> | head -30   # do the social public-search queries fit your customers?
python3 scripts/search_customers.py channels        # rows marked ▶ are the default channels; confirm they fit your industry
python3 scripts/search_customers.py queries --regions <one target country> | head -20   # do the queries look like pages where "your customers" appear?
DRY_RUN=1 python3 scripts/decision_maker_sender.py preview.json reports   # do the opening line and closing question read well?
```

A term your industry would never use appears in the queries (e.g. a software company sees "wholesale") → edit `targeting.channel_keywords` / `search.intent_terms`;
the closing question feels off → edit `offer.cta_question`.
After changing the skill package itself (scripts or docs), run `python3 scripts/consistency_audit.py`; it must report FAIL 0.
