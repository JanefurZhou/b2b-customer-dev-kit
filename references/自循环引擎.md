# 自循环客户引擎（四维轮换 · 客户池保底 · 数据触发）

> 目标：每天都有新鲜、对口的候选客户可开发；客户池永不枯竭；不把好搜的市场一次打光。
> 衡量与推进用四个维度：**高度、广度、深度、远度**。每次运行每个维度只取一个档位，逐次推进。

---

## 一、四个维度

| 维度 | 衡量什么 | 档位从哪来 | 在引擎里的落地 |
|---|---|---|---|
| **高度** | 客户价值梯队：先打最值钱的那层客户 | `targeting.customer_levels` 的顺序 = 由高到低（高价值/大客户层写在前面） | 所有地区跑完一圈后降一档 |
| **广度** | 搜索面有多宽：同一层客户换多少种找法 | `core` 核心组合 → `wide` +场景/意图轴 → `max` +全部侧翼轴（渠道站/细分/认证） | 转得最慢；整轮高度跑完才放宽一档 |
| **深度** | 同一片市场挖多深：从公司挖到人，再挖存量 | `d1_company` 公司级发现 → `d2_decision` 决策人穿透（采购链职位词） → `d3_stock` 存量深挖（成交客户/参照品牌的同类、已发未回账户的其他角色） | 转得最快：同一「地区 × 层级」连续三次运行由浅到深挖透 |
| **远度** | 市场半径与时间跨度：由近到远、长线不断供 | `targeting.target_regions` 的顺序 = 由近到远（已成交/最熟/时差最近的市场写在前面） | 深度挖完一轮后换下一个地区 |

**推进顺序**：深度（最快）→ 远度 → 高度 → 广度（最慢）。
**全覆盖一轮** = 地区数 × 层级数 × 3（深度）× 3（广度）次运行；`status` 会直接显示这个数，不再写死。
例：6 个地区 × 4 个层级 → 6 × 4 × 3 × 3 = 216 次运行，每天一次约 7 个月走完一轮，再从头按最新数据循环。

**d3 存量深挖的种子从哪来**（全部来自你自己的数据，没有就自动回落为 d2 并提示）：
- `data/success_cases.csv` 的成交客户品牌 → 搜「companies like X / X competitors / X customers」
- 档案 `targeting.reference_brands` 参照品牌 → 同上
- `data/sent_history.csv` 里已发 ≥2 封仍未回复的账户 → 搜该公司的其他决策角色（换人不换公司）

## 二、三个机制

### 机制 1：客户池保底（never dry）
- 客户池 = `$B2B_DATA_DIR/customer_db.csv`（由 `data_import.py` 生成：自有客户库 + SaaS/海关/CRM 导出 + 搜索入库）。
- **可发冷开发候选** = 有邮箱 + 未在 `sent_history` 里 + 关系不是老客户/禁联/同行。老客户走复购，不当陌生人开发。
- **双判据触发补池**（谁先破线都触发）：
  - 硬红线：可发数 < `--floor`（默认 100）。
  - 提前储备线：可发天数 < `--ahead-days`（默认 30 天）。可发天数 = 可发数 ÷ `--daily-target`（默认 100）。
- 以上三个数都是本技能的可调默认值，按你的发信能力改。

### 机制 2：四维轮换状态机
- 状态记录在 `search_state.json`：`depth_idx / region_idx / level_idx / breadth_idx / run_count / history`。
- v3.0 的旧状态文件（没有 `depth_idx`）会自动补齐，历史不丢。

### 机制 3：数据触发口 + 调度
- `triggers.py scan`：每天扫一遍客户池和各数据表，生成 `reports/trigger_queue.json`（池低、新导入文件、到期跟进、新回复、退信异常、WhatsApp 线索、预热升档、CRM 待同步、周复盘）。详见 `references/数据接入与触发口.md`。
- `search_customers.py schedule`：常驻进程，每日定点跑「检查池 → 不足则补池 → 四维轮换出词」。
- 挂载方式（平台定时任务 / cron / 常驻进程）见 `references/automation_setup.md`。

## 三、命令速查

```bash
export B2B_DATA_DIR=data          # 客户库与各数据表所在目录

# 1) 看池位够不够 + 今天轮到哪一格（不改数据）
python3 scripts/search_customers.py replenish

# 2) 自定义红线与储备、写出今日搜索词和预警
python3 scripts/search_customers.py replenish --floor 100 --daily-target 100 --ahead-days 60 \
    --emit queries_today.txt --warn-file pool_warning.txt

# 3) 池位充足也强制推进一格
python3 scripts/search_customers.py replenish --force --emit queries_today.txt

# 4) 看四维进度：下次跑哪一格、各维梯次、最近 8 次轨迹、全覆盖需要几次
python3 scripts/search_customers.py status

# 5) 常驻调度：每天 09:00 自动跑（Ctrl+C 停）
python3 scripts/search_customers.py schedule --at 09:00 --floor 100 --ahead-days 30
```

**闭环下一步**：`queries_today.txt` → 用搜索/浏览器工具逐条查公开结果 → `filter results.json --against $B2B_DATA_DIR/customer_db.csv` 去重分级 → 背调定 need_tag + solution_tag → 入 pipeline → 发信（DRY_RUN 先核对）→ 发信消耗可发池 → `triggers.py scan` 次日再判断要不要补。

## 四、推荐节奏

| 频率 | 动作 | 命令 |
|---|---|---|
| 每天（自动） | 触发口扫描 + 池位检查 + 四维补池 | `triggers.py scan`、`replenish --emit` |
| 每天（人） | 处理需人工拍板的触发；对今日搜索词逐条查证 → 去重 → 背调 → DRY_RUN → 发 | `filter` + 发信脚本 |
| 每周 | 看四维进度、池位健康、退信率；周复盘写回七件套 | `status`、`email_dashboard.py`、`triggers.py reviewed` |
| 每月 | 调整地区顺序（远度）与层级顺序（高度）；调 floor / ahead-days | 改 `company_profile.json` 后重新确认 |

---

## 五、数据铁律

本引擎只读客户库、只产出「今天该搜的词」和触发队列，绝不自动改客户数据、绝不自动发信。
入库、改标签、发邮件 / WhatsApp、推 CRM，都要经过背调和人工确认（见 SKILL.md 铁律）。
