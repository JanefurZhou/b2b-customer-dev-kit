# 客户背景调查方法论（通用版）

> 公司名/品牌名不决定需求，调研才决定。本文档是背调的详细操作指南。
> 文中所有"目标品类/工艺/卖点"都来自你首次建档时填写的 `config/company_profile.json`
> （`product.primary_keywords` / `product.one_liner_en` / `product.differentiators` /
> `offer.*`（起步方式/关键事实）与 `targeting.*`，见 SKILL.md 首次建档门禁与
> `onboarding_questions.md`），不要把任何具体行业当成默认值。
> 「品类」在本文泛指你卖的东西：产品线、软件模块、服务类型、项目能力都适用。

---

## 一、为什么必须做背调？

**三个典型教训（可迁移）：**
1. 只看公司名以为是同行，实际是目标区域内的潜在客户——别用刻板印象代替判断。
2. 网站看起来像同品类的店，实际主营是**相邻但你不做的品类**——发了也白发。
3. 只在卖"低档替代方案"的店，恰恰是**升级机会最大**的对象，差点因为"他已经在卖这类东西"而跳过。

**结论：** 公司名/品类名 ≠ 真实需求。先过**范围门禁**（是不是你建档的目标范围），再背调（需要什么、吃哪个钩子）。不做背调就发信 = 盲射。

---

## 二、背调三问框架

对每家候选公司，必须回答：

### Q1：它做什么业务？（先过范围门禁）
- 主营是不是你 `targeting` 里定义的**目标品类**（用 `primary_keywords` 及其关联词判断）
- 现有产品/方案与你的差异点是什么关系——决定"升级/替代/补充"类钩子
- 目标客群（B2B / B2C / 机构 / 项目）
- 价格定位（高端 / 中端 / 大众）

> ⚠️ 主营是建档时明确列出的**无关相邻品类**的 → 非目标，直接拦，不进入后续。
> 排除清单由你自己的行业决定（在搜索脚本配置里维护），本技能不预置任何行业的具体排除词作为默认值。

### Q2：它的渠道和立场是什么？
- 客户类型：渠道商 / 品牌方 / 集成商 / 终端企业 / 机构 / 项目方（按你的客户光谱填）
- 有无行业相关认证/合规资质（认证名以你行业真实要求为准）
- 可持续/合规定位（以你行业真实存在的标准词为准）
- 有无 wholesale / trade / vendor application / partner program / RFP / procurement 页（有 = 明确 B2B 采购信号）
- 近年战略（新产品/新服务、扩张、进入新市场、融资、新项目、换负责人、招聘相关岗位）

### Q3：它可能需要什么？
- 基于 Q1+Q2 推导 `need_tag`（要你哪条产品/服务线）和 `solution_tag`（最在意什么 → 用哪个钩子）
- 只用低档替代方案 → 推你建档的**差异化升级**卖点
- 小公司/新团队/首次尝试 → 仅当你真实有低门槛起步方式（样品/试用/试点/诊断）时，推 `low_commitment`
- 有明确节点（旺季/上线日/工期/预算窗口）→ 仅当你真实交付周期匹配时，推 `speed`
- 要独家/私牌/定制/私有化 → 仅当你真实具备定制能力时，推 `exclusive_custom`
- 信号不足 → 标 `unknown`/`review`，保守推通用方案，跟进中确认

## 三、调研信息源优先级

### 第一优先：官网（5分钟）
| 页面 | 看什么 |
|------|--------|
| 首页 | 公司定位、主营业务、客户群（先判断是不是目标范围） |
| 产品/服务/解决方案页 | 是否涉及你的目标品类；现有方案与你的差异点关系；价位或规模 |
| About / Our Story / Team | 公司背景、决策人背景、团队规模 |
| Wholesale / Trade / Partners / Procurement | 是否有批发、经销、供应商准入、合作伙伴计划、招标 |
| Sustainability / Compliance | 与你行业相关的认证、合规政策（认证名以真实存在为准） |
| Solutions / Industries / Case studies | 服务哪些行业、做过哪些项目、是否接受定制 |
| Press / News / Blog / Careers | 新品新服务、扩张、融资、新项目、招聘岗位（=预算与痛点） |

**搜索技巧：** 在官网搜你的 `primary_keywords` + 你用于区分方案的关联词 + `supplier / vendor / partner`。

### 第二优先：搜索引擎补充（3分钟）
```
- "[公司名] wholesale / vendor application / partner program / RFP / tender"
- "[公司名] <your-core-term>"
- "[公司名] launch / expansion / new project / funding <year>"
- "[公司名] site:linkedin.com <buyer_titles>"
```

### 第三优先：LinkedIn（3分钟）
- 公司页：员工规模、行业标签、近期动态
- 决策人：按 `targeting.buyer_titles`（如 procurement / CTO / HR director / operations / owner）找头衔（职位库见 `linkedin_strategy.md`）
- 用于找具名个人邮箱，避开 info@ 等通用邮箱的高退信

### 第四优先：社交媒体（2分钟）
- LinkedIn 帖子 / Instagram / YouTube / X 等：近期动态、在推什么、在抱怨什么
- 从内容判断现有方案水平、公司阶段与整体定位

## 四、调研要点（用你自己的行业填这张表）

| 调研重点 | 具体关注（示例维度，需替换成你的行业） |
|---------|---------|
| 品类匹配 | 你的目标品类关键词；建档时列出的相邻无关品类直接排除 |
| 现有方案 | 客户当前方案与你的 `differentiators` 是什么关系（替代/升级/并存） |
| 定位/规模 | 高端/大众、规模、阶段（影响推哪条线、用哪个钩子） |
| 客户类型 | 渠道商 / 品牌方 / 集成商 / 终端企业 / 机构 / 项目方（决定客户层级） |
| 认证 | 你行业真实通行、客户市场真实要求的认证 |
| 时间窗口 | 旺季、财年预算、招标周期、上线/工期节点（`speed` 钩子是否适用，取决于你的真实周期） |
| 市场 | 目标地区的合规与本地化要求；开发信语言须本地化 |

**竞品判定（通用原则）：**
- 只有**同时命中同行语义（`competitor_markers`，如 manufacturer / agency / software vendor）+ 你建档时定义的竞品地区**才排除；
- 单纯地区命中或单纯语义命中都不排除。
- 目标市场内具备同类自有产能的厂家，可定位为**产能补充/柔性外协伙伴**，是否接触由你的策略决定，
  不要用公司名一刀切标竞品。

## 五、need_tag 判定决策树（结构通用，标签名自建）

```
开始背调（已通过范围门禁）
  │
  ├─ 要你哪条线？（取值 = positioning.need_tags，按你的产品/服务库自定义）
  │   ├─ <offer-line-A>   → need_tag 记 <line_a>
  │   ├─ <offer-line-B>   → need_tag 记 <line_b>
  │   └─ 多条线/整体方案   → need_tag 记 multi
  │
  ├─ 现有方案与你的差异点关系？
  │   ├─ 只用低档替代方案     → 叠加"升级机会"标签
  │   └─ 已有同类能力/方案    → 推独家/产能/扩品类（仅在你真实具备时）
  │
  ├─ 渠道/批量特征？
  │   ├─ 小公司/新团队        → low_commitment：offer.entry_offer（用档案真实值）
  │   ├─ 有明确时间节点       → speed：offer.delivery_time（用档案真实值）
  │   └─ 渠道商/集团/大项目   → strategic_scale：容量与年度规划（用档案真实值）
  │
  └─ 无法判断品类或方案？
      └─ need_tag = unknown / review（保守，跟进中确认）
```

### 5.1 need_tag 校验铁律（必读）

1. **need_tag 只能来自背调证据**：官网产品/服务页、采购/伙伴页、认证页、新闻、招聘。不看公司名拍脑袋。
2. **每个 tag 可追溯一条证据**，写进 notes；无证据只能标 `unknown`。
3. **范围门禁优先于 need_tag**：主营不在 `targeting` 范围直接排除，不需要再定 tag。
4. **定期自查**：用搜索脚本的品类自查子命令（如 `audit-category`，若该脚本存在）输出疑似非目标清单（只挑不改），人工复核后再处理。

### 5.2 同步诊断 solution_tag（背调决定用什么钩子）⭐

> 背调不只定产品（need_tag），还要诊断痛点，从你建档的真实能力武器库匹配 `solution_tag`。
> 能力全景见 `解决方案能力.md`；取值是 11 个行业通用决策驱动（见 `industry_playbooks.md` §一），
> **但只能选你档案里真实具备对应能力的那几个**。

背调时多问一句："这家最痛的是什么？我哪个**真实**能力能解决？"

| 背调信号（通用） | 匹配能力（引用档案） | solution_tag（示例名） |
|---------|---------|-------------|
| 监管行业/招标要资质/官网有认证页 | 你真实持有的认证与文件 | `compliance` |
| 有 ESG/可持续承诺 | 可验证的可持续事实 | `sustainability` |
| 在用低一档方案，效果/质量平 | `differentiators` 中的可测差异 | `quality_upgrade` |
| 分销商/大批量/公开比价 | 起步门槛与条款（`offer.key_facts`） | `cost` |
| 小公司/新团队/首次尝试 | `offer.entry_offer`（样品/试用/诊断/试点） | `low_commitment` |
| 有节点/抱怨现供应商慢 | `offer.delivery_time`（真实值） | `speed` |
| 新产品线/新市场/融资 | 与新方向匹配的能力 | `innovation` |
| 要独家/私牌/定制/私有化 | 定制能力（如具备） | `exclusive_custom` |
| 供应商/工具分散 | 你的多线组合（如具备） | `one_stop` |
| 集团/连锁/大项目 | 产能/容量 + 年度规划（如具备） | `strategic_scale` |
| 被大供应商忽视、响应慢 | 你的真实服务模式 | `dedicated_service` |

写法（notes 字段，与 need_tag 并列）：
`solution=<tag1>+<tag2>(信号:<背调观察到的具体事实>)`

> 📖 能力武器库全景见 `解决方案能力.md`。

## 五·五、证据分级 S1 / S2 / S3（所有结论可溯源，不编造）⭐

每个 need_tag / solution_tag / 痛点判断，都要写明证据等级和来源 URL。**等级不够就不下结论。**

| 级 | 定义 | 例子 | 允许的动作 |
|---|---|---|---|
| **S1 一手** | 客户自己的官方渠道明确写的 | 官网产品页/采购页/政策页；公司 LinkedIn 页；官方账号发的招标或采购帖；海关提单显示持续进口同类货 | 直接作为 need_tag / solution_tag 依据 |
| **S2 二手可信** | 第三方或员工个人的公开信息，可交叉验证 | 行业媒体报道、展会名录、员工个人帖、评测站、招聘启事 | 可用；notes 必记来源；能补一条 S1 更好 |
| **S3 弱信号** | 推测、片言只语、无法核实 | 评论区一句话、话题标签命中、「看名字像」、相似公司类比 | **不得**据此定标签 → 标 `need_review`，交用户拍板 |

规则：
1. **至少一条 S1，或两条互相独立的 S2**，才能定 need_tag / solution_tag；否则 `need_tag=unknown` 或标 `need_review`。
2. 品牌名、域名、行业印象一律算 S3——「品牌名不决定需求，调研才决定」。
3. 写入格式（add_sent 的 notes 或背调记录）：`evidence=S1:https://...;S2:https://...`。
4. 邮件里引用客户事实，只能用 S1/S2 的内容；S3 的内容不进邮件。
5. 成功案例的痛点同样分级：AI 只出带证据的候选，用户确认后才 `add_success`。

## 六、背调时间分配建议

| 阶段 | 时间 | 产出 |
|------|------|------|
| 数据查重 | 1分钟 | 排除重复/黑名单/已发 |
| 范围门禁 | 1分钟 | 判断是否在目标范围，非目标立即拦 |
| 官网扫描 | 3-4分钟 | 主营+现有方案+客户类型+认证+动态 |
| 搜索/LinkedIn 补充 | 2-3分钟 | 采购信号、决策人、近期动态 |
| 决策定 tag | 1分钟 | need_tag + solution_tag |
| **合计** | **7-10分钟/家** | — |

批量开发可先用 2 分钟/家过范围门禁做粗分，再对通过的目标深挖。**但发信前，每家的 tag 都必须有调研支撑。**

## 七、常见误区

| ❌ 错误做法 | ✅ 正确做法 |
|------------|-----------|
| 凭地区/公司名把目标市场内的同类公司当竞品跳过 | 按"同行语义+竞品地区"双条件判定；自有产能者可定位外协伙伴 |
| 网站像目标客户就直接发 | 先确认主营在你的目标范围内 |
| 看到已在用同类方案就跳过 | 看现有方案水平，低一档方案的使用者正是升级对象 |
| 大公司用 info@ 邮箱 | LinkedIn 找 `buyer_titles` 对应决策人的具名邮箱 |
| 凭公司名印象判断业务 | 每次发信前查官网业务线确认 |
| 一次调研永远有效 | 公司可能转型/扩张，定期复查 |
| 为了凑卖点虚构门槛/周期/认证/案例 | 只用档案里可验证的真实事实 |

## 八、背调记录模板

```
公司: [公司名]
官网: [URL]
国家: [国家]
客户层级: [按你的客户光谱，如 L1_core / L2_... ]
主营业务: [一句话]
现有方案: [与你 differentiators 的关系：替代/升级/并存]
采购信号: [vendor/partner/RFP/招聘/扩张/认证/无]
need_tag: [<line_a>/<line_b>/multi/unknown]
solution_tag: [compliance/cost/speed/low_commitment/...（仅限你真实具备的能力）]
调研来源: [官网/搜索/LinkedIn/...]
备注: [特殊发现，如新产品、扩张、融资、招标、换负责人等]
```

实际使用中，tag 写入客户库/`sent_history.csv` 对应字段或 notes，其余信息记录在任务日志中。
