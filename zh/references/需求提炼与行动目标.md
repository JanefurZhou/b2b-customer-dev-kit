# 设计原则与行动目标（通用版总纲）

> 方法：这套技能不是"看到问题就改"堆出来的，而是把真实 B2B 客户开发过程中反复出现的
> **每一类需求/教训**提炼出来（合并同义），变成**可执行的规则与脚本行为**。
> **核心诉求：不重复劳动，让 AI 更高效、且不编造。**
> 通用版的使命：帮任何行业的使用者学会"怎么思考着用 AI 做客户开发"，并直接会用这套方法
> —— 所以要保留**值得思考的方法论**；
> 技能本身：**考虑全面，但用户用起来简单**（复杂留给脚本/流程，简单留给使用者）。
>
> 说明：本文是技能内部设计备忘。所有具体行业事实均已抽象为「建档配置」，
> 由使用者在首次建档时填入 `config/company_profile.json`。

---

## 一、核心规则（从实战教训提炼，已合并同义）

| # | 规则 | 行动目标 | 落地 |
|---|------|----------|------|
| **R1 搜索转化率低** | 自动范围门禁判太激进会误杀目标；取数硬截断会丢结果；邮箱门槛太高会丢优质品牌 | 多客户层级扩面 + 竞品判定收窄（需同时命中制造国+制造语义）+ 全量域名去重不截断 + 按邮箱质量分级入库 | 搜索脚本/流程 |
| **R2 不做重复劳动**（核心） | 搜新客户前没先查已有客户库，结果"三家全在库里，白搜半天" | 搜索前**强制先查客户库**；命中即跳过 | `--against` 库比对；SOP 前置节点 |
| **R3 表格按时间迭代成可积累库** | 主表持续追加，按 `added_date` 排序；搜索只比对近 N 月（增量），不必每次读全表 | 一张主表持续追加 + 时间窗 | `--since` 时间窗；csv_guide 迭代规则 |
| **R4 需求标签误判** | 只凭公司名/类目名判断客户在做什么，必然出错；标签必须由官网等背调证据决定 | need_tag/品类 **由背调证据决定、绝不看品牌名**；提供只挑不改的自查脚本 | 铁律；`audit-category` 自查；research_guide |
| **R5 表内重复记录** | 同一品牌多条（有具名邮箱/免费邮箱/空邮箱）需合并 | 库内去重：同品牌多条按"有具名邮箱 > 免费邮箱 > 空"合并 | csv_guide 去重规则 |
| **R6 通用邮箱退信铁证** | 真实批量实测中通用邮箱（info@/sales@ 等猜测/角色地址）退信率极高，具名邮箱显著更好 | 通用邮箱不直接发冷邮件（铁律）；分级为 B（先补决策人具名邮箱） | 铁律；分级逻辑 |
| **R7 决策人多渠道** | 决策人不只出现在一两个渠道，要按市场排渠道优先级 | 12 渠道全景 + 按地区 if/else 优先级 | SOP_客户搜索详细流程 |
| **R8 备用池连续性** | 客户池必须有提前量，避免每天临时找客户 | 设可发池保底红线与储备天数；定期检查补池 | SKILL / SOP 周期任务 |
| **R9 发前三道关 + 合规** | 邮箱验证→查重→查备注；字数控制；禁用词；禁追踪像素；凭证不入库 | 发送前三关；合规检查 | SOP 发送步骤 |
| **R10 多级跟进冷却** | 递进跟进 + 逐级冷却 + 最终停发转替代渠道（LinkedIn/WhatsApp） | 多级递进闭环 | SOP 跟进步骤 |
| **R11 成功案例复盘** | 回复→AI 分析痛点→**用户确认后才记录**；启动前先复盘 | 第 0 步复盘；痛点 AI 只建议、决策权在人 | SOP 第 0 步 |
| **R12 看板读统一表** | 看板数据源统一读取主客户表，避免多表口径不一 | 看板数据源 = 主客户数据表 | dashboard_guide |
| **R13 上架安全合规** | 只用标准库、不引第三方依赖；凭证全走环境变量、拒绝明文 SMTP、强制 STARTTLS/SSL、IMAP 校验证书 | 通用版代码合规：**高危=0、中危=0** | 脚本 + 合规声明 |
| **R14 通用版彻底脱敏** | 通用版**不含**任何真实产品库/手机号/域名/联系人，全部用占位符 + 建档配置 | 真实信息只存在于使用者自己的私有档案；技能包可公开分发 | 打包分离 |

## 二、两条使命拆解

**A. 通用版 + SOP = 教人"怎么思考着用 AI"**
- 不只给"怎么做"，还要给"为什么这么做"（每个 if/else 背后的实战教训，如通用邮箱高退信率、激进门禁误杀目标）
- 提炼**可迁移的方法论**：客户光谱思维、背调决定需求、分级而非一刀切、增量而非全量、数据驱动复盘
- 让使用者换个行业也能照着思考、照着用

**B. 技能本身 = 全面但简单**
- 全面：脚本把复杂逻辑（去重/分级/时间窗/合规）封装好
- 简单：使用者只需少量命令（生成搜索词 → 搜索 → 过滤查库分级 → 拿候选），不需要懂内部实现

---

## 三、提效要点（服务"不重复+高效"）

1. 搜索前自动查库（R2）→ `--against`
2. 按时间只读近期数据（R3）→ `--since`
3. 全量域名去重（R1）
4. 需求标签自查纠错（R4）
5. 铁律：任何搜索/开发前必先查库

---

## 四、验收标准

- [ ] R1 搜索：客户光谱分层 + 放宽过滤 + 全量去重 + 邮箱质量分级
- [ ] R2 不重复：搜索前置查库；命中跳过
- [ ] R3 时间迭代：主表追加 + `--since` 增量
- [ ] R4/R5 数据质量：need_tag 自查 + 表内去重规则
- [ ] R6-R12 全流程 SOP 逻辑闭环反映最新逻辑
- [x] R13 通用版合规（高危=0、中危=0；凭证走环境变量 + 强制加密传输 + 拒绝明文）
- [x] R14 通用版脱敏到位：无真实公司/产品/联系人，占位符 + 建档配置
