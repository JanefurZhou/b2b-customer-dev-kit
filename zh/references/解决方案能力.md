# 核心解决方案能力武器库 + 背调诊断映射（通用版）

> **核心逻辑（因果顺序，不可颠倒）：**
> 不是「我们有几个能力，挨个往客户身上套」，而是
> **背调 → 诊断客户痛点 → 匹配解决方案能力 → 定制钩子话术**。
> 能力全景是「武器库」，背调结果才是「扣动哪把武器的扳机」。
>
> 与 need_tag 同源思想：
> - `need_tag`（客户要你哪条产品/服务线）由背调证据决定 → 决定推**什么**
> - `solution_tag`（最吃哪个解决方案钩子）由背调证据决定 → 决定用**什么价值主张打动他**
>
> **两个标签都只能由背调证据决定，绝不看品牌名、绝不拍脑袋。**
>
> ⚠️ 本文是**通用模板**：下表列出的是「能力类别」骨架，**你自己的真实能力与对应话术
> 全部来自首次建档时填写的 `config/company_profile.json`**（`product.differentiators` /
> `product.one_liner_en` / `offer.entry_offer` / `offer.key_facts` 等，
> 见 SKILL.md「首次建档门禁」与 `onboarding_questions.md`），并可在
> `references/product_knowledge.md` 里展开维护。任何没有真实证据支撑的能力，不得写进武器库。

## 一、解决方案能力（武器库 · 全行业骨架）

> 使用方法：对照下面的能力类别，只保留**你真实具备**的行，把「英文钩子方向」替换成
> 建档时 `product.differentiators` / `offer.*` 中你自己的真实表述。`<...>` 占位不得原样出现在对外邮件里。
> 右侧「不同行业的样子」只帮助你对号入座，不是你的事实。

| # | 能力类别 | 不同行业的样子 | 因此能开发谁 | 钩子方向（英文，替换为真实事实） |
|---|---|---|---|---|
| ① | **核心差异** `differentiators` | 工艺/材料 · 公差/良率 · 功能/性能 · 方法论/结果 | 在用低一档方案、有升级意愿的客户 | "<your-verifiable-advantage>" |
| ② | **起步门槛** `offer.min_commitment` | MOQ · 最小批量 · 最短订阅 · 起步套餐 | 小公司、新团队、首次尝试者 | "start from <your-min-commitment>" |
| ③ | **低风险入口** `offer.entry_offer` | 样品 · 打样 · 免费试用 · 试点 · 免费诊断 · 样板 | 谨慎型、要先验证的客户 | "<your-entry-offer> before any commitment" |
| ④ | **交付时效** `offer.delivery_time` | 打样+大货周期 · 上线周期 · 项目工期 · 运输时效 | 有明确节点的客户 | "<your-delivery-time>, ready for your <deadline>" |
| ⑤ | **定制能力** | 私牌/ODM · 定制开发 · 私有化部署 · 专属方案 | 要独家/差异化/定制的客户 | "<custom capability — state fact only>" |
| ⑥ | **一站式范围** | 多品类/多形态 · 多模块 · 全流程服务 | 供应商/工具分散的客户 | "<scope A> and <scope B> from one team" |
| ⑦ | **服务模式** | 专属对接 · SLA · 驻场 · 本地支持 | 怕被大供应商忽视的中小客户 | "<your actual service commitment>" |
| ⑧ | **合规与资质** | 产品认证 · 质量体系 · 数据安全认证 · 执业资质 | 监管行业、招标、ESG 采购方 | "<exact certification name>" |
| ⑨ | **容量与规划** | 产能 · 年度排产 · 并发项目数 · 团队规模 | 集团、连锁、大项目、框架采购 | "<capacity fact>, planned with you" |
| ⑩ | **配套支持** | 物流清关 · 集成/迁移 · 培训 · 融资/账期 | 不熟悉跨境或实施的客户 | "<the actual support you provide>" |

**填写与使用原则：**
- 能力事实**只能来自建档档案与产品/服务知识库**，AI 不得自行虚构门槛、周期、认证、客户案例。
- 最强差异化杠杆因人而异：复盘你自己的成交案例（`success_cases.csv`），
  统计哪类钩子实际带来回复/订单，再决定武器排序。

## 二、背调痛点 → solution_tag 诊断映射表（11 个通用取值）

> 背调时，除了判定 need_tag（要你哪条线），还要诊断**最在意什么**，从你真实具备的能力里匹配 `solution_tag`。
> 取值固定为行业通用的 11 个（脚本 `decision_maker_sender.py` 直接识别）；你只需要删掉自己不具备的行。

| 背调发现的痛点/信号（任何行业） | 诊断出的缺口 | 匹配能力 | solution_tag |
|---|---|---|---|
| 监管行业、招标要资质、官网有认证页 | 合规门槛 | ⑧ | `compliance` |
| 有 ESG/可持续承诺或采购政策 | 可持续要求 | ⑧ + ① | `sustainability` |
| 在用明显更低一档的方案，有升级迹象 | 方案升级缺口 | ① + ⑤ | `quality_upgrade` |
| 分销商/大批量采购/公开比价 | 成本压力 | ② + ⑨ | `cost` |
| 体量小、首次尝试、怕投入 | 起步门槛高 | ② + ③ | `low_commitment` |
| 有节点、抱怨现供应商慢 | 时效不足 | ④ | `speed` |
| 新产品线/新市场/融资/新项目 | 新方向缺能力 | ① + ⑥ | `innovation` |
| 要独家/私牌/定制/私有化 | 同质化 | ⑤ | `exclusive_custom` |
| 供应商/工具分散 | 整合需求 | ⑥ | `one_stop` |
| 集团/连锁/大项目方 | 稳定 + 规划 | ⑨ + ⑩ | `strategic_scale` |
| 被大供应商忽视、响应慢 | 缺被重视的服务 | ⑦ | `dedicated_service` |

**一家客户可有多个 solution_tag**（由背调信号决定，可叠加；发信时取第一个作主钩子）。
旧版标签（`low_moq` / `upgrade_opportunity` / `seasonal` / `exclusive_design` / `category_expand` /
`strategic_partner` / `eco_only` / `traditional` 等）会被脚本自动映射到新取值，历史数据不用改。

## 三、solution_tag 存法

发信 JSON 直接带 `solution_tag` 字段（脚本优先读取它选钩子）；客户库里写进 `notes` 字段，与 need_tag 证据并列，可追溯：

```
notes: need_tag=<line_a>(证据:官网<具体页面/动态>) | solution=<tag1>+<tag2>(信号:<背调观察到的具体事实>)
```

## 四、闭环：解决方案能力如何反向驱动全流程

```
搜索（按建档的目标客户类型/关键词扩面找候选）
   │  每类客户对应一个真实能力 + 要找的痛点客户
   ▼
范围门禁（不属于建档 targeting 范围的直接拦）
   ▼
背调（诊断痛点，看证据不看品牌名）
   │  产出双标签：need_tag(定推哪条线) + solution_tag(定钩子)
   ▼
邮件（按 solution_tag 选钩子，事实全部引用 company_profile）
   │  从「我们卖什么」→「我们能解决你的哪个具体难题」
   ▼
发信 → 跟进 → 成交 → 复盘（用真实成交反推武器排序）
```

- 背调诊断步骤见 `research_guide.md`。
- 钩子/邮件措辞见 `email_templates.md`（其中的占位符在建档后替换为你的真实事实）。
