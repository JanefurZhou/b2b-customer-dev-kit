# 周复盘写回：错在哪，就写回哪份文件

> 来源：soul-seven-kit 的「复盘写回」方法，已接进本技能的「第零步 全渠道复盘」与「第八步 成单复盘 + 七件套写回」。
> 触发：每周一次（建议与 `csv_ops.py review_success` / `wa_review.py review` 同一天跑）。

## 三步

1. **翻记录**：本周对话、HEARTBEAT、发信报告（`batch_report_*.json` / `decision_maker_report_*.json`）、退信扫描结果。只找三类问题：答错了什么 / 漏做了什么 / 越没越界。
2. **归因**：每个问题定位到**唯一一份**档案。
3. **写回**：改规则，不只改这一句回答；写回后更新 HEARTBEAT 的「人工介入」与「下次优化点」，再跑 `python3 scripts/onboarding.py kit-check`。

| 现象（客户开发场景） | 病因 | 写回哪份 |
|---|---|---|
| 邮件口径/语气前后不一 | 说话方式没定 | SOUL.md |
| 换个对话就不清楚自己服务哪类客户 | 身份没写清 | IDENTITY.md |
| 漏了查库去重 / 背调 / 三道关 | SOP 有漏洞 | AGENTS.md |
| 没等老板确认就发了 / 报了价 | 刹车没写或不清 | AGENTS.md |
| 用错脚本、字段写错、DRY_RUN 没先跑 | 工具用法没交代 | TOOLS.md |
| 同一个坑踩第二次（如通用邮箱冷邮） | 坑没记下来 | TOOLS.md |
| 忘了池子状态、重复问背景 | 状态没更新 | MEMORY.md |
| 汇报格式不对 | 老板偏好没写 | USER.md |
| 出错没记录、无法排查 | 没留日志 | HEARTBEAT.md |
| 到点该跑的补池/复盘没跑 | 日程没写进档案 | AGENTS.md 或 HEARTBEAT.md |

**找不到该改哪份 → 说明档案没写清，回到那份档案重写。**

## 节奏

| 频率 | 动作 |
|---|---|
| 每天 | 发现答错当场改档案 |
| 每周 | 完整三步复盘，写回所有归因；更新 MEMORY「上次复盘结论」 |
| 每月 | 档案太厚就固化稳定部分、删过时内容 |

## 对用户的复盘汇报模板

> 本周复盘发现 N 个问题，归因如下：
> 1. <现象> → <哪份档案缺什么> → 已补进 <文件>
> 2. …
> 七件套体检 7/7 通过，HEARTBEAT 已更新。
